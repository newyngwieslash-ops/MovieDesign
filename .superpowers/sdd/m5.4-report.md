## Product behavior and exact handoff

- React 19 TipTap composer with custom `mention` node whose authority is `attrs.path = asset:<ID>`. Mention lookup uses the existing project asset query; displayed thumbnail URL uses project-scoped gateway content with `crossOrigin=anonymous`. Keyboard suggestions support arrows/Enter/Escape, atom deletion, and IME guard. StarterKit retains nested list/blockquote JSON. Only the approved TipTap packages were installed, exactly `3.32.0`: core, react, pm, starter-kit, extension-mention. Their transitive packages are locked. No test, Markdown, sanitizer, popup or rendering dependency was added.
- Full document, display text, unique ordered nested mention IDs and annotation snapshots are serialized once before POST. `AssetLibrary.onAnnotations` forwards the real ImageEditor's image-pixel annotations plus owning project/asset/version identity. Explicit “附加当前标注” snapshots them into chat and inserts the source asset mention. The retained draft shows its source data. Existing mask generation, sourceVersionID, export recovery, canvas editing and generation composer are preserved. The editor is keyed by asset **and version** to avoid relabelling old geometry when one asset appears in different versions.
- GET sessions/history uses the existing gateway helper and bounded 100-row pagination, as required by chat's API (the asset helper's independent limit is 200). The server owns queue ordering. Accepted user records remain visible; queue editing first persists and POSTs an immutable withdrawal, then requires observed `cancelled` before explicit loading of the old document for a new send/new request ID. No replacement sends automatically.
- Separate validated `moviedesign.chat.{create,send,cancel}.v1.<project>` journals store exact original bodies **before** writes. Existing journals must match before replay or cleanup. Unknown create/send/cancel inputs survive remount, project switch and restart. All recovery is explicit. Corrupt/unreadable storage blocks writes visibly. A late unmounted completion cannot delete a newer journal. A definite public 400-class rejection (excluding ambiguous 408/409/429) releases the rejected intent so the draft can be corrected; other errors retain the original input.
- Chat uses only the existing singleton project SSE transport. Its session filter follows project cursor advancement. History GET is authoritative on reconnect. `reduceEvent` distinguishes session/message/step/part/call and terminal states, and ignores old IDs. Because history GET has **no event watermark**, the rendered UI invalidates/reads history on content deltas instead of appending a delta that could already be included in the snapshot. Replacements/tool snapshots/terminal updates can project immediately; GET always reconciles. There is no second SSE or browser queue.
- Assistant text, reasoning, tool names/input/output and user content render as React text, never HTML. No Markdown execution or raw native envelope is exposed. UI explicitly describes the existing supplier-response buffering limitation instead of promising first-token streaming.
- Existing `ConfirmationCard` remains the only reply/reject authority. It now displays `native_send_state`; superseded cards retain the existing nonactionable behavior. Real native testing exposed stale delivery projection after the human receipt: the existing cards subscriber now also invalidates on chat events. A committed card still pending/sending gets at most 15 one-second GET refreshes, with cleanup on dependency/unmount, then manual refresh remains available. No approval or native reply transport was added.

Public API/schema/backend changes: **none**. No edits to gateway or native runtime. `events.ts`, `ImageEditor.tsx` and CanvasWorkspace did not require changes: their existing APIs already cover the integration. Ownership was minimally extended (parent acknowledgement) to the existing `scripts/check-m2-ui.mjs` App import stub and its WebCrypto scheduling wait, because adding App's ChatPanel broke the old controlled loader, and a preexisting 100-event-loop-tick deadline flaked under concurrent build load. The check now waits on the actual completion predicate with a bounded wall-clock deadline.
