## 1. 总览

MiniMax Design 实际上有**三个不同层次的"画布"**，很容易混淆，先厘清：

| 层 | 是什么 | 技术实现 | 位置 |
| --- | --- | --- | --- |
| **A. 图像标注编辑器** | 图片上画矩形/椭圆/箭头/文字/马赛克的编辑器 | 自研 Canvas 2D 引擎（本文主体，约 3,000 行核心代码） | p0 `bundle.js` 50,638–53,300 |
| **B. 图像滤镜后端** | 调色/滤镜实时渲染 | 自研 WebGL/WebGPU 双后端 + 13 种片元着色器 | p0 46,455–49,000+ |
| **C. v3 创作画布** | 无限画布工作台（多媒体节点、生成结果、agent 编排） | React + gateway REST 协议（节点上限 10,000） | p3（协议客户端） |

**A 是 B 和 C 的粘合层**：用户在 A 上框选区域+写注释（标注），提交给 agent（走 C 的会话），生成结果在 C 的画布上呈现，预览用 B 的滤镜调色。本文按 A→B→C 顺序完整覆盖。

### 1.1 核心类图（恢复源码实证）

```
Editor（命令中枢，52669）
 ├── renderer: Renderer（四层合成，52363）
 │    └── processedCache: Map<mode-strength, canvas>（马赛克/模糊 LRU，52362）
 ├── bus: EventBus（发布订阅，52252）
 ├── history: HistoryManager（快照栈，52283）
 ├── shapes: Shape[] + shapeMap: Map<id, Shape>
 ├── currentTool: Tool（多态分派，53228 makeTool）
 └── textarea: HTMLTextAreaElement（文字叠加层，52984）

Shape（抽象基类，50638）
 └── Rectangle / Ellipse / Line / Arrow / FreePath(brush) / Text / Tag / Mosaic

Tool（抽象基类，51682）
 └── Select / DrawShape(rectangle|ellipse|line|arrow) / Brush / Mosaic / Text / Tag
```

## 2. Shape 家族

### 2.1 基类契约（p0:50638-50667）

```typescript
class Shape {
    data;                       // 纯数据对象 = 序列化格式本身
    get id() / get type() / get style()   // 代理 data
    drawSelection(ctx, uiScale)           // 通用虚线选框 #3370FF，随 uiScale 反缩放
}
```

**关键设计：数据与行为分离**。`this.data` 就是序列化格式（`addShape(data)` / `bus.emit("shape:add", cloneShapeData(data))`），Shape 实例只是行为的载体。`cloneShapeData()`（52654）做深拷贝（style 展开、points 逐点复制）——这是历史快照与事件负载的统一形态。

**每个子类实现 4 个方法**：`draw(ctx)`（绘制）、`hitTest(p)`（点选检测）、`getBounds()`（包围盒）、`move(dx,dy)` / `resize(bounds)`（变换）。

### 2.2 八种图形的实现细节（全部逐行核实）

**RectangleShape（51136）**
- 拖拽产生负宽高（`x + width`，width<0）时 `getBounds()` 归一化
- 命中检测的巧思：`fill` 存在 → 填充命中（pad=strokeWidth）；无 fill → **环形命中**：`pointInBounds(p,b,+pad) && !pointInBounds(p,b,-pad)`——只有描边区域可选中

**EllipseShape（50749）**
- 绘制用 `ctx.ellipse(cx,cy,rx,ry)`；命中分两路：有 fill → `pointInEllipse`（内部），无 fill → `pointOnEllipseStroke`（描边±pad）

**LineShape（50872）**
- 命中 = 点到线段距离 `distanceToSegment(p,a,b) <= max(8, strokeWidth)`——**最小命中半径 8px** 是全部图形的统一可用性下限
- `resize` 按包围盒比例缩放两个端点（`sx = b.width/cur.width`），零尺寸退化保护

**ArrowShape（50668）**
- 自绘箭头：头长 `max(12, strokeWidth*4)`、头宽 `max(8, strokeWidth*3)`；箭体截短 `headLen*0.5` 让头盖住线端；垂直向量 `(perpX,perpY) = (-uy,ux)` 计算头两翼——**纯几何三角函数，无图标资源**

**FreePathShape（笔刷，50799）**
- **二次贝塞尔平滑**：中间点作为控制点、相邻中点作为端点（`quadraticCurveTo(p[i], mid(p[i],p[i+1]))`）——标准手绘平滑算法
- 单点特例：画 `strokeWidth/2` 半径的圆点（点一下=画个点）
- `addPoint(p)` 是唯一增量 API——拖拽时只 push + 重绘 preview

**MosaicShape（马赛克，50956）——最复杂的一个**
- 两种形态：`shape:"rectangle"`（矩形遮罩）或 `"brush"`（笔刷路径遮罩）
- 绘制需要 `helpers.getProcessedSource(mode, strength)`——**马赛克不是滤镜效果，是把处理后的底图裁剪进遮罩区域**（`ctx.clip()` 后 drawImage 处理图）
- 笔刷遮罩用**双缓冲**：临时画布先画处理图，`globalCompositeOperation = "destination-in"` 只保留笔刷路径区域（同贝塞尔平滑），再 drawImage 回主画布
- `brushTmp` 画布**复用**（只增不减尺寸）——高频笔刷操作的内存优化
- resize 的细节：先收缩 `brushSize/2` 再算缩放比（`innerCur`），保持笔宽视觉稳定

**TextShape（51540）**
- 三种变体 `textVariant`：`plain`（纯填充）/ `filled`（色块卡片，pad 按 fontSize 比例）/ `outlined`（描边字）
- **对比色算法**：`pickContrastColor(mainColor)`——按 `(r*299+g*587+b*114)/1000 > 165` 亮度阈值自动选反色（p0:2134637 附近找到同款公式）
- **resize = 改字号**：纵向比例直接换算 `fontSize`（`Math.max(8, round(fontSize*ratio))`），位置对 filled 变体做 pad 补偿——文字缩放语义与图形不同

**TagShape（标注气泡，51194）——产品级细节密度最高**
- 圆角卡片（`CORNER_RADIUS 6`）+ 指针（`POINTER_BASE 8 / HEIGHT 4`）+ 锚点圆点（半径 2.5），中文字体栈 `"PingFang SC", "Microsoft YaHei"` 写死
- **自动换行** `wrapTagLines()`：逐字符 measureText（对 CJK 正确）
- **防遮挡摆放**（`keepTagInCanvas`，51336）：优先反侧（锚在左则卡片放右）→ 不行试同侧 → 再不行夹紧到画布内 margin=4
- **锚点吸附**：`inferSide()` 判断锚在卡片哪个方向，`computeAnchorPosition()` 把锚点修到该侧中点——拖动时指针永远指向合理位置
- `getBounds` 把锚点圆点也算进包围盒（选中框完整）

### 2.3 序列化格式（从数据对象反推的 schema）

```jsonc
// 矩形
{ "id":"rect_lx2k_3f", "type":"rectangle", "x":10, "y":20, "width":100, "height":80,
  "style":{ "stroke":"#FF3B30", "fill":undefined, "strokeWidth":3 } }
// 线/箭头: x1,y1,x2,y2
// 笔刷: points:[{x,y}...]
// 文字: { x,y,text,width,height, style:{fontSize,fontFamily,fontWeight,textVariant,textOutlineColor} }
// 标注: { x,y,anchorX,anchorY,width,height,text,maxWidth, style:{tagBackground,tagTextColor,tagAnchorRadius} }
// 马赛克: { shape:"rectangle"|"brush", x,y,width,height | points,brushSize, mode:"mosaic"|"blur", strength }
```

`uid()` 生成器（51678）：`sh前缀_36进制时间戳_36进制计数器`（防同毫秒碰撞，模 1000000）。

## 3. Tool 家族

### 3.1 基类（p0:51682）

```typescript
class Tool {
    editor; cursor = "default";
    onPointerDown/Move/Up(_e) {}   // 空实现，子类覆写
    onDoubleClick/onKeyDown(_e) {}
    onActivate/onDeactivate() {}   // 工具切换生命周期
}
```

事件流：`canvas.pointerdown/move/up/cancel → Editor.handlePointer* → 坐标变换 → currentTool.onPointer*(e.point)`。**工具对 Editor 的操作全部走公共 API**（setPreviewShape/addShape/beginInteraction/commitInteraction）——工具不知道渲染细节。

### 3.2 各工具状态机（逐行核实）

**DrawShapeTool（矩形/椭圆/线/箭头共用，51734）**——经典三态：

```
idle --down(左键)--> drawing（buildInitialData → setPreviewShape）
drawing --move--> drawing（updateShape：矩形取 min+abs 规范化；线段直接赋端点）
drawing --up--> idle（太小的丢弃：线/箭头判位移<4，矩形/椭圆判包围盒<4；否则 addShape(data)）
```

**BrushTool（51696）**：down 创建 FreePathShape 入 preview；move 只 `addPoint + requestPreviewRender`；up 时 `points.length > 1` 才提交——**单点笔刷不产生形状**（与 FreePathShape 绘制单点的能力对不上，是有意的交互约束）。

**SelectTool（51953）**——最丰富的状态机：

```
idle:
  hover 已选中 → hitHandle? 显示 cornerCursor(nwse/nesw) : hitTest? "move" : default
down:
  已选中 + 命中四角手柄(8px/uiScale) → mode=resize{corner, start, original}, beginInteraction
  已选中 + hitTest → mode=move, beginInteraction
  未选中 → findShapeAt（**倒序遍历** = 顶层优先）→ select + mode=move
  点空处 → select(null), mode=idle
move:
  move 态: dx,dy 相对 start，对 original 平移（不是累积！）→ selected.resize({orig.x+dx,...})
  resize 态: computeResize(original, corner, point) —— 四角独立约束对边，翻转安全（min/abs）
up: mode != idle → commitInteraction()（历史入栈）
key: Delete/Backspace → deleteSelected；Escape → select(null)
```

**要点**：移动是**绝对差值重放**（每次 resize 到 original+delta），不做累积增量——避免浮点漂移；手柄命中半径 `8/uiScale` 随缩放反比，屏幕上永远 8px。

**MosaicTool（51835）**：按 `style.mosaicShape` 分派矩形/笔刷两套拖拽逻辑；`pickStrength()` 把风格映射为马赛克块尺寸（`mosaicBlockSize ?? 12`）或模糊半径（`blurRadius ?? 8`）；预览用蓝色 `#3370FF` 1px 矩形（id 硬编码 `"preview"`）。

**TextTool（52229）**：三行代码——down 即 `editor.openTextEditor(point)`，全部复杂度在 Editor 侧（§7）。

**TagTool（52152）**——拖拽定向放置：

```
down: 记锚点，建占位 TagShape（44×26），默认放右侧
move: 位移≥8px（MIN_DRAG_DISTANCE）后按主轴方向切卡片侧向（|dx|>=|dy| ? 水平 : 垂直）
up: addShapeInstanceWithoutHistory（避免空文本进历史）→ openTagTextEditor(id) 直接进入文字编辑
```

**设计精髓**：拖的方向决定气泡出现在锚点哪侧——一个手势完成"指到哪+放哪侧"两个决策。

## 4. Renderer：四层画布与增量合成

### 4.1 层结构（p0:52363）

```
main（DOM 上的可见 canvas）
  = bgLayer      ← 当前底图（drawBackground）
  + shapeLayer   ← 全部已提交形状（drawShapes）
  + previewLayer ← 拖拽中的预览形状（drawPreview）
  + 选框叠加     ← 直接画在 mainCtx（drawSelectionOverlay，不入层）
```

**离屏层都是物理像素尺寸**（`width * pixelScale`），主画布 `setTransform(scale)` 统一坐标系——**形状逻辑坐标是 CSS 像素**，与 DPR 无关。

### 4.2 pixelScale 逻辑（52376，推断处标注）

```javascript
get pixelScale() {
    const baseScale = this.dpr * this.uiScaleTier;        // 设备像素比 × UI 缩放档
    if (imageNaturalWidth > 0 && width > 0)
        return Math.max(baseScale, imageNaturalWidth / width);  // 大图超采样
    return baseScale;
}
```

**推断**：显示尺寸小于原图时按原比例放大物理缓冲（`naturalWidth/width`），保证导出与显示的一致精度；`uiScaleTier = ceil(uiScale)` 防止 UI 缩放时每帧抖动重分配。

### 4.3 调度：requestAnimationFrame 合帧（52584）

```javascript
requestRender(job) { this.pending.add(job); if (rafId===null)
    rafId = requestAnimationFrame(() => { rafId=null; composite(); }); }
composite() { pending.clear(); … drawImage(bg,shape,preview) + selectionOverlay }
```

**pending 是 Set 但 composite 无视内容全量重绘**（观察）——job 去重的意义是合帧而非真增量；一次拖拽 60 次 move 只产生 1 次合成。bg/shape 层本身只在内容变化时重绘（`clearCanvas + drawImage`），拖拽预览只动 previewLayer——**三层分离使预览重绘成本恒定**（一个形状），与形状总数无关。

### 4.4 马赛克缓存（52362 + 52563）

`processedCache: Map<"mode-strength", canvas>`，LRU 容量 8（`PROCESSED_CACHE_LIMIT`）：命中即提升到 Map 尾部，超出逐最旧。`generateBlur` 用 edge-clamp（四面各复制 8 次 1px 边）+ `ctx.filter` 硬件模糊；`generateMosaic` 是 downsample(smooth)→upsample(nearest) 的经典两步法。**尺寸/DPR 变化时 `processedCache.clear()`**（52458）。

### 4.5 DPR 监听（52471）

用 `matchMedia('(resolution: Ndppx)')` 监听设备像素比变化（跨窗口拖到另一屏时触发），变化后重建监听（新阈值）——比监听 resize 精确。

### 4.6 导出（52548）

`exportComposed()` 按原图 naturalWidth/Height 建独立画布，`setTransform(exportScale)` 把形状按显示坐标系**重绘**（不是截图合成层）——导出分辨率独立于屏幕。

## 5. Editor：命令中枢

### 5.1 交互事务：beginInteraction / commitInteraction（52958-52977）

**这是整个编辑器最重要的语义**：

```javascript
beginInteraction()   { if (interactionSnapshot===null) interactionSnapshot = cloneShapesData(); }
commitInteraction()  { history.push(interactionSnapshot ?? cloneShapesData()); interactionSnapshot=null;
                       renderer.drawShapes(); renderer.setSelected(); emitChange(); }
cancelInteraction()  { interactionSnapshot = null; }
```

任何修改（addShape/removeShape/deleteShapes/clear/选中形状改样式/setStyle 作用于选中项/SelectTool 拖拽结束）都包裹在 begin…commit 里。**一次拖拽 = 一次快照入栈**（begin 时拍交互前状态，up 时 commit）——undo 一次回退整个拖拽，而不是一帧。

嵌套保护：`beginInteraction` 幂等（已有快照则跳过）——TagTool 的 addShapeInstanceWithoutHistory + 文本编辑组合不会重复入栈。

### 5.2 公共 API 全集（52669-53300，逐行核实）

| 类别 | 方法 |
| --- | --- |
| 工具 | `setTool(name)`（deactivate→make→activate→emit "tool:change"）、`getTool` |
| 样式 | `setStyle(patch)`（合并到全局 style；**作用于选中形状时包交互事务**，MosaicShape 特判同步 mode/strength/brushSize） |
| 形状 | `addShape(data)`、`addShapeInstance(shape)`、`addShapeInstanceWithoutHistory`、`removeShape(id)`、`deleteShapes(ids)`、`deleteSelected`、`clear()` |
| 选择 | `select(id)`、`getSelectedShape`、`findShapeAt(p)`（倒序=顶层优先） |
| 历史 | `undo/redo`（clone 当前→history.undo(prev)→applySnapshot(prev)） |
| 文本 | `openTextEditor(point, existing?)`、`openTagTextEditor(tagId)`、`closeTextEditor(commit)` |
| 输出 | `toDataURL(type,quality)`、`toBlob`、`getComposedSnapshot()`（bg+shape 合成，不含 preview/选框） |
| 图像 | `loadImage(src)`（**版本号防竞态**：`imageLoadVersion` 递增，异步回来版本不符直接丢弃）、宽高按图纵横比自适应 |
| 状态 | `getState()`（shapes/selectedId/tool/style/canUndo/canRedo 的纯数据快照）、`on/off`（bus 转发） |

### 5.3 事件总线（52252）

EventBus 是无类型的 `Map<type, Set<handler>>`，`emit` 里 try/catch 每个 handler（**单个监听器抛错不中断广播**）。事件目录（源码观察）：`"change"`（每次提交）、`"ready"`（图载入）、`"error"`、`"tool:change"`、`"select"`、`"shape:add"`、`"shape:remove"`、`"shape:update"`（文本编辑提交时）。

### 5.4 快照恢复的实例保活（applySnapshot，53256）

undo/redo **不是销毁重建**：`oldMap.get(id)` 命中则 `Object.assign(old.data, data)` 复用实例（保住 MosaicShape 的 brushTmp 画布等内部态），未命中才 createShape。selectedId 指向已消失形状时清空。

## 6. HistoryManager

（p0:52283-52323，全文 41 行）双栈 + 容量 50：

```
push(s):  undoStack.push(s)；超限 shift 丢最旧；redoStack 清空（新动作截断重做分支）
undo(cur): prev=undoStack.pop() → redoStack.push(cur) → 返回 prev
redo(cur): 对称
```

**快照式而非命令式**：每栈条目是全量 `cloneShapeData()[]`。对标注场景（形状数 <几百）这是正确的选择——零合并冲突、实现 41 行；若形状数上万则需换命令模式（该场景由 v3 Canvas 协议层承担，见 §10）。

**Editor.undo 的入参设计**：`undo()` 先 `cloneShapesData()` 作为"当前态"传给 history——保证 redoStack 里是用户所在状态，与栈语义精确对应。

## 7. 文本编辑：透明 textarea 叠加

**问题**：Canvas 没有文本输入能力，自绘光标/选区/IME 是深坑。
**方案**（52984-53227，约 240 行）：**叠一个透明 textarea 在画布上**，样式精确对齐：

```javascript
Object.assign(ta.style, {
  position:"absolute", background:"transparent", border:"none",
  color:"transparent", caretColor: mainColor,        // 文字透明、光标可见
  fontSize/fontFamily/fontWeight/lineHeight: 与 TextShape.draw 完全一致,
  outline:"1px dashed #3370FF"                       // plain 变体的编辑框
});
```

**输入回路**：`input 事件 → shape.data.text = ta.value → renderer.drawShapes()` ——**canvas 上实时按最终渲染效果显示文字**（textarea 只提供输入/光标/IME），每帧用 `measureText` 换算（autoResizeTextarea 撑宽）。

**提交语义**（closeTextEditor(commit)，53157）——一张判定表：

| 情形 | commit=true（blur/回车） | commit=false（Escape） |
| --- | --- | --- |
| 新建 text | 空白→删除+入栈；有字→入栈+"shape:add" | 从 shapes 移除 + cancelInteraction（不入栈） |
| 编辑已有 text | 空白→删除+"shape:remove"；有字→"shape:update" | 恢复 originalText + cancel |
| tag | 空白→删除；有字→"shape:update" | 删除 |

**边界**：新建时夹紧到画布内（minX/minY 限制，防在边缘打出看不见的字）；filled 变体的 textarea 关 outline 只留 caret。Tag 编辑实时 `keepTagInCanvas` 防卡片出界。

## 8. WebGL/WebGPU：滤镜后端

（p0:46455-49000+，与 2D 标注层同文件但独立子系统）

### 8.1 双后端架构

```
BaseBackend（抽象）
 ├── WebGLBackend（46455）  getType()="webgl"，isSupported() 探测
 └── WebGPUBackend（47899）
```

**输入源四种**：`loadFromImage / loadFromImageData / loadFromVideo / loadFromSource`（视频帧与 ImageBitmap），统一 `UNPACK_FLIP_Y_WEBGL` + `sourceNeedsFlipY` 记录（ImageBitmap 需要手动翻）。

### 8.2 WebGL 的程序矩阵（46681-46734，观察）

一次 `initResources` 建 **13+ 个着色程序**，每滤镜一个片元着色器 + 统一顶点（全屏双三角形）：

`pass / vibrance / saturation / temperature / tint / hue / brightness / exposure / contrast / blacks / whites / highlights / shadows / dehaze / …`

- `saturation`、`contrast` 用 **3×3 色彩矩阵** uniform（`uMatrix[0]`）——CPU 算好矩阵 GPU 一次乘
- `blacks` 单独用 blackVertexSource + **调色板纹理**（`createPaletteTexture(buildBlackPalette(level))`，`lastBlacksPalette` 缓存）——黑阶用查表而非数学，`lutParams` 增量更新
- `getImageData()` 用 `readPixels` 回读（preserveDrawingBuffer:true 是它的前提，46476）

### 8.3 LUT 调色（46591）

`setLUT(lut)` → `lutToFlat2D(lut)` 展平为 2D 纹理上传；`setLUTParams` 增量。**对应资源层的 `gateway/dist/luts-presets`**（第二篇发现）——滤镜预设从 gateway 下发，后端只管渲染。

**ImageColorGrading**（48957）是这层的对外门面（推断：组装 settings 并分发给 backend.render）。

## 9. React 消费层

### 9.1 ImageEditor 组件（p0:2111061）

`forwardRef` 薄封装，职责纪律极清：

- **挂载即建**：`useLayoutEffect` 里 `createEditor(...)`，ref 存 editor 实例；卸载 destroy
- **回调经 ref 逃逸**：`callbacksRef.current.onChange = props.onChange`——回调更新不触发编辑器重建（编辑器实例依赖 `[]`）
- **受控面最小**：src 变化 → `loadImage`；uiScale 变化 → `setUiScale`
- **imperativeHandle 暴露**：`setTool/setStyle/undo/redo/clear/deleteSelected/loadImage/toBlob/toDataURL/getEditor/getSize`

### 9.2 useEditorState（p0:2111061 之后）

订阅 `"change"` → setState；**带 retry 的 attach**（编辑器可能晚于 hook 就绪）。组件树因此拿到 `canUndo/canRedo/tool/...` 的响应式快照驱动工具栏。

### 9.3 标注工作流（p5:1,244,000+）——编辑器与 AI 的接合部

这是产品上"画框告诉 AI 改这里"的实现，**用编辑器的原语拼出来**：

```
用户画矩形（shape:add 捕获，type==="rectangle" 且 ≥MIN_RECTANGLE_SIZE）
  → draft = { rectangleId, bounds, comment:"" }，选中它并切到 select 工具
  → rAF 循环 syncBounds（拖拽实时更新 draft.bounds）
  → 用户写 comment（updateDraftComment）→ 提交
  → 矩形 + comment 配对成为 annotation（tag 气泡由 TagShape 渲染在同一编辑器上）
  → annotations 数组随消息发送（chat 面板渲染 SentAnnotationCards / PendingAnnotationList）
  → agent 在会话里拿到 (区域, 文字) 指令对，驱动图像编辑
```

**防御细节**（逐行核实）：Delete 键先判 `isComposing`（中文输入法回车误删防护）；焦点在 input/textarea/contentEditable 时跳过编辑器快捷键；删除 draft 与删除 annotation 走不同路径（draft=cancelDraft 恢复 rectangle 工具，annotation=deleteShapes([rect,tag]) 成对删除）；`handleEditorChange` 里检测 select 工具且无 draft 时**自动弹回 rectangle 工具**（引导画下一个框）。

**这套工作流没有引入任何新图形原语**——矩形+标注气泡两个既有 Shape + 事件总线即成。是"编辑器 API 设计对了，上层就便宜"的直接证据。

## 11. 设计模式总结（可复用清单）

按值得抄的程度排序：

1. **数据即序列化格式**：Shape.data 就是 wire format，无 ORM/无转换层。事件负载、历史快照、导出全用同一个 `cloneShapeData`。
2. **交互事务（begin/commit/cancel）**：任何用户手势一个事务，快照入栈点在 commit。undo 粒度=手势粒度，天然正确。
3. **三层画布 + preview 隔离**：拖拽重绘成本 O(1)（只画 preview 层），与形状总数解耦；合成靠 rAF 合帧去重。
4. **透明 textarea 文字输入**：Canvas 应用文字编辑的标准解，光标/IME 白嫖浏览器，渲染自己来。判定表见 §7。
5. **工具对象 + Editor API 门面**：Tool 只调 Editor 公共方法，加工具=加一个类+makeTool 一行，不碰渲染。
6. **命中检测的可用性下限**：`max(8, strokeWidth)` ——触屏时代图形再细也点得中；矩形无填充时环形命中是同类思路。
7. **马赛克=裁剪处理图**而非滤镜：`getProcessedSource` + LRU(8) + clip/destination-in——遮罩类工具的通用做法。
8. **resize 语义按类型分派**：几何图形缩坐标，文字缩字号，马赛克保笔宽——多态吞掉了差异性。
9. **版本号防异步竞态**：loadImage 的 `imageLoadVersion` 两个 async 交错时旧结果静默丢弃。
10. **applySnapshot 实例保活**：undo 复用实例保内部态（brushTmp 画布），避免撤销闪 alloc。
11. **回调 ref 逃逸**：React 封装层里 callbacks 走 ref，props 变化不重建重对象。
12. **标注工作流零新原语**：矩形+Tag 两个既有 Shape 拼出"画框指令 AI"功能——好 API 的复利。
